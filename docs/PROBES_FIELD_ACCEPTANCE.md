# BLOODSKY NET — приёмка Distributed Probes на физических компьютерах

**Статус: НЕ ПРОВЕДЕНА.** GitHub-hosted Windows CI и локальный loopback не доказывают прохождение испытаний двух реальных ПК.

## Стенд

Два отдельных Windows 10/11 x64 ПК с разными IP в разрешённой сети; приёмник A и отправитель B, опционально третий ПК C. Запишите версии Windows, сетевых адаптеров, тип подключения, время UTC, результат и системные логи. Используйте тестовые адреса только с разрешения администратора сети.

## Проверки (пока без подтверждения)

- [ ] В чистой установке приложение не открывает слушающий порт, автоотправка выключена.
- [ ] На A вручную разрешить приём TLS и локальный порт в Windows Firewall. На B проверить отпечаток сертификата A **по отдельному доверенному каналу**.
- [ ] Выдать отдельные ключи отправителям B и C. Убедиться, что импортированная метка JSON не выдаётся за аутентифицированный компьютер.
- [ ] Успешная передача и журнал UTC на A, затем проверка значения ICMP только как заявления удалённого клиента.
- [ ] Ошибка TLS PIN и неверный/отозванный ключ: обмен не проходит, автоотправка остановлена. В журнале нет секретов.
- [ ] Выполнить смену сертификата A: B блокирует старый PIN, новый подтверждается вручную по доверенному каналу; автоматического принятия нового PIN нет.
- [ ] Отключить сеть B на 20 минут и восстановить; проверить backoff, отсутствие ложного «компьютер выключен» и ручное включение при необходимости.
- [ ] Прогон 24 часа с потерей Wi-Fi, повторным подключением, спящим режимом, переполнением очередей и перезапуском обоих ПК.
- [ ] Проверить 7-дневное ограничение записей и восстановление истории после перезапуска, отсутствие паролей/токенов в SQLite и экспорте.
- [ ] Запустить установщик и удаление на Windows 10 и Windows 11 без прав администратора; проверить штатное закрытие слушателя.

## Доказательства для закрытия

Таблица результатов, скриншоты окон, таймстампы UTC, хеши EXE/installer, журнал принятия/отклонения, конфигурация тестовых машин и список неустранённых проблем. До выполнения всех критических пунктов **релиз 1.0 не выпускать**.

## Дополнительные испытания защиты 0.33.0-dev (ещё не выполнены)

- [ ] Повторно передать тот же свежий пакет: ответ HTTP 409.
- [ ] Заполнить кэш повторов: новые пакеты получают HTTP 503, старые ID остаются защищёнными от повторной передачи.
- [ ] Незавершённый TLS handshake или неполное тело запроса одного клиента не мешает работе второго клиента.
- [ ] После 20-минутного отключения сеть восстанавливается без автоматического доверия новому сертификату.
- [ ] Проверить отзыв личного ключа между двумя реальными Windows-ПК и убедиться, что логи не содержат секретов.

Локальные и GitHub-hosted тесты **не подтверждают** эти аппаратные проверки. Gate 1.0 дополнен критериями `probe_two_real_pcs`, `probe_identity_revoke` и `probe_outage_recovery`, которые остаются `not_run`.
