# BLOODSKY NET 1.0 — полевой протокол приёмки

**Статус:** НЕ ПРОЙДЕН / ожидаются реальные Windows 10/11 и управляемые коммутаторы.
Автоматическая сборка в GitHub Actions не подтверждает работу в пользовательской сети.

## Перед проверкой

1. Используйте только собственную или разрешённую локальную сеть.
2. Скачайте установщик/EXE и контрольные суммы из одной и той же сборки Windows CI. Проверьте `Get-FileHash -Algorithm SHA256`.
3. Подготовьте два реальных ПК (Windows 10 и Windows 11) и два управляемых коммутатора разных производителей для SNMPv3/LLDP/FDB. Если оборудования нет, оставьте критерий `blocked`, не ставьте `pass`.
4. Используйте учётную запись SNMP **только на чтение**. Не записывайте её пароль, community и реальные сетевые идентификаторы в отчёт или issue.

## Фиксация результатов

Создайте локальный шаблон (он весь в состоянии `not_run`):

```powershell
python tools/release_gate.py --template acceptance-1.0.json
```

Проводите испытания из [issue #15](https://github.com/skynet909084-boop/BLOODSKY-NET/issues/15). Для каждого пункта отмечайте `pass`, `fail`, `blocked` или `not_run`. При `pass` заполните `environment` и `evidence` безопасной ссылкой на локальный протокол/идентификатор испытания **без секретов, IP/MAC, имён людей**. Проверка самого файла:

```powershell
python tools/release_gate.py --check acceptance-1.0.json
```

Выход `1` означает незавершённую приёмку, `2` — ошибку формата, `0` — что **все строки вручную** помечены пройденными и имеют ссылку на подтверждение. Код `0` сам по себе не доказывает, что человек действительно проводил тесты: перед релизом нужен просмотр первичных доказательств.

## Запрет на преждевременный релиз

- Не публиковать «1.0 stable», пока хотя бы один критерий #15 не подтверждён.
- Не заявлять подписанный EXE без реальной проверки Authenticode и легального сертификата.
- Не смешивать тесты в GitHub-hosted Windows VM с испытаниями на физических ПК и реальных управляемых коммутаторах.
- Не включать в отчёты пароли, SNMP community, ключи, внутренние IP/MAC, BSSID или пользовательские данные.
